# v0.7.8 Public Release Documentation Design

## Goal

Make the public repository describe the release that users can actually install: `v0.7.8-beta - Install & Onboarding Polish`.

A visitor should see the current beta version, understand its newly added first-run and diagnostics improvements, and be able to open a matching in-repository release note without encountering stale `v0.7.7-beta` links.

## Context

`v0.7.8-beta` is published on GitHub from `main`. It contains the Install & Onboarding Polish milestone and the mobile first-run floating-control fix.

The current public source documents still call `v0.7.7-beta` the current release:

- `README.md` release badge link and current-beta paragraph
- `ROADMAP.md` current public beta direction

The repository also has release-note files through `docs/releases/v0.7.7-beta.md`, but no matching `v0.7.8-beta.md` file.

## Scope

### README

Update the release badge target and current-beta paragraph to link to `v0.7.8-beta`.

The current-beta summary should accurately combine the already-published beta capabilities with the new release's user-visible additions:

- first-run empty-library guidance
- Config Local Setup summary
- `image-prompt-library status` and clearer `doctor` output
- Windows Git Bash installer compatibility
- first-run mobile controls no longer covering onboarding content

Keep the existing public-demo, privacy, attribution, and local-only generation wording unchanged.

### Roadmap

Set the current public beta version to `v0.7.8-beta`.

Move install/onboarding polish out of the near-term priority list because it is released. Leave service/update hardening, cleanup, batch editing, mobile Explore, generation hardening, and import work as future work.

### In-Repository Release Note

Add `docs/releases/v0.7.8-beta.md` in the existing release-note format.

It should state:

- the release title and its install/onboarding focus
- the first-run empty-library, Config, CLI, and Windows installer improvements
- the first-run mobile overlap fix
- the verification evidence: GitHub PR CI, frontend build, focused tests, and independent desktop/mobile visual review
- that GitHub Pages remains read-only and no local data is bundled
- the exact update command: `image-prompt-library update --version v0.7.8-beta`

Do not claim that the Windows-hosted full suite is entirely green; the release note may point to the established platform caveat if needed.

## Non-Goals

- No application, installer, frontend, or backend behavior change.
- No release retagging or modification of the already-published GitHub Release.
- No translation rewrite or documentation formatting sweep.
- No new screenshots, generated assets, dependencies, or marketing site.
- No change to the next product milestone decision.

## Verification

- Search public source docs for stale `v0.7.7-beta` current-release links and confirm none remain outside historical release notes.
- Verify each v0.7.8 link points to the published GitHub release tag.
- Review the release note for consistency with the published release and merged PR scope.
- Run `git diff --check`.

## Acceptance Criteria

- The README badge and current-beta paragraph identify and link to `v0.7.8-beta`.
- The roadmap identifies `v0.7.8-beta` as the current release and no longer lists completed onboarding work as near-term.
- A release note exists at `docs/releases/v0.7.8-beta.md` with accurate release, verification, and update information.
- No claim exceeds the evidence recorded for the release.
