# v0.7.10 OAuth Reliability Hotfix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make token-endpoint HTTP 408 and refresh-lock open failures safe, temporary, and redacted without weakening real OAuth credential errors.

**Architecture:** Keep all behavior in `CodexNativeAuthStore`. Extend the existing temporary-error classification at the token response boundary and translate only lock-file open `OSError` values into the same neutral `CodexNativeTemporaryError`. Existing `read_tokens()`, provider status, and generation-job handling then preserve the session and classify the failure as `provider_unavailable` without API or UI changes.

**Tech Stack:** Python 3.10+, FastAPI, httpx, pytest, pathlib, standard-library context managers.

## Global Constraints

- Use `Token refresh is temporarily unavailable` as the only new-or-reused user-visible error text.
- HTTP `400`, `401`, and `403` must remain `CodexNativeAuthError` cases.
- Never include an auth path, lock path, operating-system error text, access token, or refresh token in a status or generation-job failure message.
- Do not add dependencies, retries, endpoint fields, frontend changes, or stale-lock cleanup.
- Keep Windows `msvcrt` and POSIX `fcntl` advisory-lock behavior unchanged after a lock file opens successfully.

    lock_path = auth_path.with_name(f"{auth_path.name}.refresh.lock")
    store = CodexNativeAuthStore(auth_path)

    def fail_open(self, *args, **kwargs):
