# Image Prompt Library v0.8.1 - Safer Generation and Updates

v0.8.1 focuses on clearer recovery when image generation fails and safer application updates across Windows, macOS, Linux, and WSL.

## Highlights

- Classified generation failures now reuse `GenerationJob.metadata.error_kind` to give actionable guidance for policy, rate-limit, provider availability, authentication, and unknown failures without exposing unsanitized provider responses.
- Authentication-required guidance reuses the existing Config → Providers flow, while retry, queue recovery, result review, provenance, and reference behavior remain unchanged.
- OAuth and provider configuration paths are rejected when they resolve inside the active private library, keeping credentials outside backup, sample-data, and public-demo boundaries.
- Windows can detect source versus release installs and present the appropriate update path without treating source checkouts as packaged releases.
- POSIX install, update, and rollback now use stricter release manifests, confined paths, transaction locks, verified runtimes, atomic pointer replacement, and handled-interruption recovery.
- Release publication binds the manifest to the exact source commit, publishes only the archive, checksum, and manifest, then downloads and verifies those assets again before publication.

## Compatibility boundary

The current POSIX installer requires the `posix-shell-v1` release capability. Legacy v0.8.0 assets predate that capability and the literal `.env` loader used by v0.8.1. A v0.8.1 rollback therefore fails closed when the previous POSIX payload does not contain the required safe runtime files; the release does not silently reactivate the legacy shell-evaluated `.env` behavior. Windows uses its separate `windows-powershell-v1` contract.

## Validation

The release gate uses the public GitHub release assets and clean default user paths to exercise install, explicit update, diagnostics, private-library preservation, and rollback on `windows-latest`, `macos-latest`, and `ubuntu-latest`. A failure on any platform keeps the GitHub release marked as a prerelease. These checks do not require a paid image-generation request.

Power loss, `SIGKILL`, or an operating-system crash between POSIX pointer replacements is still not treated as a durable journal transaction. Run `image-prompt-library doctor`, then retry the update or use a validated rollback target.
