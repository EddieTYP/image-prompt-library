# Image Prompt Library v0.8.2 - POSIX v0.8.0 Rollback Compatibility

v0.8.2 is the current stable compatibility fix for POSIX installations. It supersedes v0.8.1 as the latest release but does not retag or replace v0.8.1.

## Exact v0.8.0 rollback migration

- A rollback target whose directory name and `VERSION` are exactly `v0.8.0` is preflighted and offline-health-checked before any overlay write.
- A first migration requires `scripts/load-env.sh` to be absent and the three public v0.8.0 management scripts to match their shipped SHA256 fingerprints. A modified or unprovenanced target fails closed. A previously started migration is accepted only when its marker and each existing file match the exact state authorized by the same controller.
- The current controller migrates only the installed-command management plane: `scripts/install.sh`, `scripts/load-env.sh`, `scripts/install-sample-data.sh`, and `scripts/appctl.sh` (with `appctl.sh` replaced last). `backup.sh` and source-development scripts are not copied.
- Backend, frontend, `VERSION`, `.venv`, private library, auth/config files, and `current`/`previous` pointers remain unchanged. The literal allow-listed environment loader keeps `.env` values as data rather than shell code.
- Directory file descriptors anchor every migration read, temporary, replacement, and cleanup to the already-validated physical source and target directories. Each file is written through a no-follow, same-directory fsynced temporary and atomic replacement. Exact regular stale temporaries are reconciled on retry; symlink/non-regular exact remnants fail closed and near-match paths remain preserved.
- A `prepared` provenance marker is made durable before the first overlay write. It records schema, target version, source controller version, and intended file SHA256 values, allowing a partially completed overlay to reconcile after interruption. The marker changes to `complete` only after all four files are durable; it never bypasses revalidation.
- Non-v0.8.0 incomplete targets continue to fail strict validation without mutation. Windows uses its existing separate controller contract.

The operating-system account remains the local trust boundary: an actor who can replace the running controller can also change its code and marker. Within that boundary, modified legacy payloads, mismatched markers, symlinks, non-regular files, and directory-swap attempts are rejected. A freshly bootstrapped, untouched v0.8.0 install remains the supported baseline.

## Verification

Before stable promotion, the public release-candidate smoke installed the baseline and candidate from their published assets, updated, rolled back, verified that `current` was v0.8.0 and `previous` was the candidate, compared all four migrated scripts against the candidate under `previous`, validated the complete provenance marker and `load-env.sh`, then ran `status`, `doctor`, and a private-library sentinel check.
