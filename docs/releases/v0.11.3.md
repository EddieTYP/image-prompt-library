# Image Prompt Library v0.11.3 — release preparation

This version is not published yet. `v0.11.2` remains the current stable release. These notes describe the maintenance changes planned for `v0.11.3`; they do not announce availability or completion of release-candidate acceptance.

## Generation reliability and context

- Replaying a generation submission with the same request ID and payload returns the original job or set instead of creating a duplicate. Reusing the ID with different content is rejected. This is local submission deduplication, not a guarantee of exactly-once execution by the provider.
- Generation status makes stale polling and uncertain timeout outcomes clearer. A transport timeout does not prove the provider stopped processing; review the existing job before retrying. Partial polling failures preserve known generation state.
- Saving results updates the generation-set summary. Image-specific prompt context and generation quality choices are preserved more consistently when reviewing and reusing results.
- Mobile collection filters no longer extend horizontally beyond the drawer. Long names retain the existing ellipsis treatment while reference counts stay visible.

## Database upgrade and backup compatibility

The upgrade adds migration `012_generation_creation_requests.sql`, containing the request ID, payload hash, result ID, and creation time used for submission deduplication. It does not remove existing Library tables or media. Reopening the Library does not apply the migration twice.

| Operation | Compatibility |
| --- | --- |
| Open a schema-011 Library from v0.11.2 in the new version | Adds migration 012; tested baseline item, prompt, job and media remain available |
| Restore a v0.11.2 backup using the new version | Supported; migration is applied in restore staging |
| Back up and restore a schema-012 Library using the new version | Supported; submission receipts survive restore and replay returns the same job |
| Run v0.11.2 code against a migrated Library | Limited compatibility only: synthetic item/job reads and a job write passed; migration 012 remains present and the old version lacks the new submission-deduplication behavior |
| Use v0.11.2 to back up a migrated Library or verify/restore a schema-012 backup | Rejected because the migration ledger is newer than that version understands |
| Restore the pre-upgrade v0.11.2 backup using v0.11.2 | Supported; returns to the old snapshot, not a merge of later changes |

**Application rollback does not downgrade the Library schema.** Returning to the old executable alone is not a fully compatible recovery: v0.11.2 backup operations reject the upgraded Library. Do not edit the migration ledger or remove migration 012 manually to bypass validation.

Before upgrading, keep a verified v0.11.2 backup outside the Library. If a full return to v0.11.2 is necessary, stop the application, preserve the upgraded Library and its backups, and restore the pre-upgrade backup with the old version. Items and jobs created after that snapshot will not be in the restored active Library. Restore preserves the replaced Library as a sibling `.pre-restore-*` directory; retain it for recovery. To use a schema-012 backup, use the new version again.

## Acceptance completed and still required

Completed during preparation:

- Isolated source-level comparison of the exact v0.11.2 tag (`e3d2ecd`) with the planned runtime changes (`24b0836`). Synthetic fixtures verified baseline backup, migration, repeated startup, job-receipt replay, old-code reads/writes, explicit rejection of newer backups without changing the active fixture, re-upgrade, and both restore directions described above.
- Main CI and Pages passed for `24b0836`. The deployed demo was checked at 390px and 320px: collection drawer horizontal overflow was zero, and search, collection selection, image details and closing worked.
- Public Codex OAuth upstream configuration drift check passed. This is not live login or image-generation acceptance.

Still required before stable promotion:

- Build the exact candidate archive, manifest and checksum; verify source identity, contents, privacy exclusions and version labels.
- Run the public release-candidate install/update/rollback and backup/restore smoke on Windows, macOS and Linux, explicitly using **v0.11.2** as the baseline. Source-level compatibility tests do not certify those installer paths.
- Validate the candidate's real generation/edit workflow and error recovery with an authorized provider session. No paid generation, credential access or provider login was performed for this compatibility check.
- Review the rollback limitation above and ensure users retain a verified pre-upgrade backup.

The current candidate workflow uses a bare version tag marked as a GitHub prerelease before stable promotion. Creating that candidate is a publishing action and has not been performed as part of this preparation.
