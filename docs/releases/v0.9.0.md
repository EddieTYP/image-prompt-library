# Image Prompt Library v0.9.0 - Generation Sets and Portable Recovery

v0.9.0 combines the generation-set workflow already merged after v0.8.2 with a versioned, credential-free portable backup and safe restore contract.

## Generation sets

- Generate 1, 3, 5, or 10 independent jobs from one prompt and ordered reference set.
- Run at most five jobs concurrently while keeping additional jobs queued.
- Show exact set and per-job progress on desktop and mobile.
- Pause a provider queue on rate limits, prefer `Retry-After`, use bounded backoff when it is absent, and continue jobs that have not started.
- Keep completed results, individual Retry, review, discard, provenance, and reference behavior unchanged.

No paid provider request is required to verify these queue, progress, retry, and recovery contracts.

## Portable backup and safe restore

Installed Windows, macOS, and Linux releases now provide:

```text
image-prompt-library backup
image-prompt-library verify-backup <archive>
image-prompt-library restore <archive> --yes
```

The versioned `.tar.gz` archive contains `manifest.json`, a consistent SQLite snapshot, accepted library media, pending generation results, and copied generation references. It uses fixed relative paths plus per-file size and SHA-256 checks. OAuth tokens, provider configuration, device-login/session state, logs, installer state, and backup directories stay outside the payload allowlist.

The running app and archive commands share one cross-platform library lock. Restore validates identity, paths, member types, checksums, SQLite integrity, foreign keys, migration compatibility, and referenced media before replacing anything. A known older schema is migrated only in staging. The previous active library is preserved as a sibling after a successful restore and is restored automatically when a handled publication failure permits it; a fresh-machine restore can publish to a missing active-library path.

Checksums detect accidental corruption; they are not cryptographic signatures. A backup is private recovery data and may contain prompts, notes, provenance, imported source paths, and generation history deliberately stored in SQLite.

## Compatibility and limits

- Stop the app before backup or restore; commands do not silently stop or restart generation work.
- Former manifest-less `backup.sh` archives are not imported automatically because they are incomplete and machine-path-dependent.
- Restore replaces one library; it does not merge libraries or import arbitrary archives.
- Handled failures roll back safely. Automatic reconciliation after an abrupt power loss during the final two-directory switch remains out of scope; recovery remnants are retained for manual inspection.
- Cloud backup, sync, scheduling, encryption, incremental backup, and an in-app Restore control remain out of scope.
- GitHub Pages remains read-only and credential-free.

## Release gate

Stable promotion requires the normal public asset checks plus Windows, macOS, and Linux install/update/rollback smoke, portable backup round-trip, deliberate corruption rejection, safe restore, migration/privacy regression checks, and preservation of the pre-restore library. No real paid generation request is part of the automated gate.
