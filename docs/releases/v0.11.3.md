# Image Prompt Library v0.11.3

Planned maintenance release; not yet published. The current stable release remains [v0.11.2](https://github.com/EddieTYP/image-prompt-library/releases/tag/v0.11.2). Normal install and update commands do not yet select these changes.

This release improves generation submission recovery and makes queue status and timeout guidance clearer.

## Recover a submission without creating duplicate jobs

If a submission response is lost, check the work queue first. Retrying the exact same content, settings, references, and count in the same browser tab reuses the unacknowledged request ID, including after a page reload. The server returns the original job or batch instead of creating another one. Rapid repeated clicks are also guarded while submission is in progress.

This protection applies to job creation, not to retrying a failed provider execution. A changed submission, a new tab or device, cleared browser storage, or another generation after an acknowledged response is a separate request. It may generate another image and incur another charge.

The browser's submission-recovery record contains only a request ID and payload digest, not prompt text or reference image bytes. If session storage is unavailable, submission stops before sending an untrackable request.

## Clearer generation status

- Saving or attaching a generated result immediately updates its batch summary.
- If generation status cannot be refreshed, the panel warns that the displayed information may be out of date and provides a **Refresh status** action. This action reads status; it does not submit another generation.
- Temporary failures while fetching individual jobs preserve their last known state. A confirmed missing job is removed instead. A successful refresh clears the warning.
- Failed results no longer retain the earlier queued-message text.

## Timeouts do not confirm that generation stopped

ChatGPT / Codex and Grok image-generation transport timeouts and HTTP `408` / `504` responses now show an uncertain-outcome warning. The provider may still be processing the image, and a charge may already apply. Check provider activity before manually retrying; retrying may produce another image and another charge.

These timeout paths do not automatically retry the image request. The guidance is available in English, Traditional Chinese, and Simplified Chinese.

## Updating and validation

Back up your Library before updating. This release adds a database migration for durable generation-submission receipts; portable backup and restore validation includes the new table.

The implementation has passed automated tests and main-branch CI, including Windows installer and macOS backup/restore checks. Release-candidate asset verification and Windows, macOS, and Linux install/update/rollback checks remain required before stable publication. Mock-provider tests verify timeout handling without making paid generation requests; they do not establish live provider availability or billing outcomes.
